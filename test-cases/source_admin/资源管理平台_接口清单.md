# 资源管理平台接口清单

## 分析基线

- 上游仓库：`https://gitlab.ituchong.com/ai-dataset/ai-source-admin`
- 分支：`master`
- 基线 commit：`55040a84d1d711ed4198215bc61be43b93ab1d85`
- 分析日期：2026-09-10
- 主文档：上游 `docs/api.md`
- 交叉材料：上游 `docs/*-api.json`、生成路由 `biz/router/ai/data/manage/*`、自定义路由 `router.go`

## 结论摘要

`docs/api.md` 当前列出 40 个需登录 Token 的接口，覆盖数据管理、文件系统、Schema、分享链接和审计日志 5 个业务域。上游 4 份 OpenAPI JSON 与生成路由共确认 49 个操作；另有 9 个操作已经存在于结构化契约和代码中，但未写入 `docs/api.md`，后续测试接入应以“代码路由 + 结构化契约”补齐，而不是遗漏它们。

统一响应约定在主文档中写为 `code`、`msg`、`data`；数据管理部分的若干接口使用扁平响应（例如 `base`、`collections`、`total`），需要在接入契约时以对应 OpenAPI JSON 和实际响应为准，不能直接套用同一个响应断言。

## 认证与入口边界

| 入口范围 | 认证方式 | 证据 | 接入结论 |
| --- | --- | --- | --- |
| `/api/v1` 生成路由 | `Authorization: <token>`，由 `middleware.Auth()` 校验 | `docs/api.md` 开头；各模块 `middleware.go` 的 `_v1Mw` | 40 个主文档接口及 9 个结构化契约补充接口默认归入此域 |
| `/api/v1/public/share/:token` | 分享 Token，中间件为 `ShareTokenAuth()` | `router.go`、`biz/handler/share.go` | 非登录 API，不应沿用 Bearer Token fixture |
| `/api/v1/public/collections/:collection_id/*` | 分享 Token，数据接口还会增加浏览次数 | `router.go` | 公开分享读取链路，单独建匿名/分享 Token 场景 |
| `/api/v1/hbase/*`、`/api/v1/devtools/*` | `HBaseAuth()` 固定凭证 | `router.go` | 属于 HBase/DevTools 专用入口，不纳入本轮 49 个主业务操作 |
| `/api/v1/composite/preview` | `router.go` 未挂登录中间件；`data-manage-api.json` 有全局 Bearer 声明 | `router.go`、`docs/data-manage-api.json` | 认证规则冲突，列入未决项，不能猜测 |

## 主文档与结构化契约差异

| 差异 | 证据 | 影响 |
| --- | --- | --- |
| 主文档 40 个操作，结构化 JSON/路由 49 个操作 | `docs/api.md`；4 份 `docs/*-api.json`；生成路由 | 清单和后续 Schema 覆盖矩阵必须以 49 个为基线，9 个补充接口需回补主文档或明确非目标 |
| `api.md` 总响应写成 `data` 包裹，但数据管理示例大量使用 `base`/扁平字段 | `docs/api.md`；`docs/data-manage-api.json` | 不能使用一个通用 JSON 路径断言所有接口 |
| 分享创建示例只含 `name`、`collection_id`，结构化契约要求 `expire_at` | `docs/api.md` 第 831 节；`docs/share-api.json` | 创建接口的必填参数和生命周期规则未统一 |
| 审计操作类型枚举不一致 | `docs/api.md` 第 893 节；`docs/audit-api.json` | 按类型筛选的预期不能直接生成测试断言 |
| `composite/preview` 的全局 Bearer 声明与自定义路由未挂 `Auth()` 不一致 | `docs/data-manage-api.json`；`router.go` | 认证正向/无 Token 预期未定 |
| 主文档未写分页上限、名称/字段长度、错误码和 4xx/5xx 响应结构 | `docs/api.md` | 参数边界和错误响应无法凭文档确定 |

## 业务依赖关系

```text
Schema -> SchemaField -> TOS 同步/版本快照/回滚
Schema + 文件节点 -> SQL 构建 -> 圈选任务 -> Collection
Collection -> labels/data/node-path/columns/set-type/download
Collection A/B -> 集合运算 -> 新 Collection
Collection -> ShareLink -> 公开分享读取链路
文件节点 -> CSV 上传地址 -> CSV 检查 -> 异步导入 -> 状态/错误查询
写操作 -> AuditLog
```

## 当前未决项

以下问题会影响后续客户端、数据工厂和自动化用例，不在本轮用假设填充：

1. 测试环境的资源管理平台 Base URL、认证 Token 获取方式，以及 Token 是否需要 `Bearer ` 前缀。
2. 是否允许在测试环境执行 Schema、字段、节点、集合、分享链接和 CSV 导入等写操作；清理接口/回收站恢复策略是什么。
3. 异步任务的轮询超时、状态稳定判定和失败码：原始下载、圈选、集合运算、CSV 导入分别采用什么阈值。
4. 所有接口的错误码、错误响应结构、资源不存在时的 HTTP 状态码与业务码。
5. 分页参数的最小值、最大值、默认值和是否包含边界；名称、`qualifier`、SQL、CSV 文件等字段的长度/格式上限。
6. `composite/preview` 以路由实现还是 OpenAPI 安全声明为准。
7. 分享链接 `expire_at` 是否必填、时区/时间单位，以及 `max_count=0` 的实际含义。
8. 审计操作类型以 `api.md` 的 1-5 还是 `audit-api.json` 的 1-4 为准。
9. HBase、Hive/LanceDB、TOS、RPC 数据服务等依赖是否有可用测试替身或固定测试数据；若无，哪些接口只做契约检查。
