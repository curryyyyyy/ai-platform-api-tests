# AI 平台接口测试

使用本技能时，要在保持仓库架构边界的前提下完成框架或接口测试变更。最终结果应是小而可追溯的改动，并保持已提交契约快照、客户端、数据、Schema、覆盖映射、测试和平台文档一致。

## 开始前

编辑前：

1. 阅读适用范围内的 `AGENTS.md`，再执行 `git status --short`；保留用户已有的无关改动。
2. 确认目标平台，阅读 `tests/<platform>/README.md`、`platforms/<platform>/contract.yaml`、客户端、工厂或预置器、数据 YAML、契约快照、接口清单、覆盖矩阵和受影响测试。
3. 沿完整链路追踪目标用例或接口：testcase/Schema -> 覆盖映射 -> pytest 函数 -> 平台客户端 -> 公共 HTTP 客户端 -> 已提交 OpenAPI 快照。
4. 选择最小归属边界。通用行为放在 `framework/`；URL、业务字段、状态预置和清理细节放在 `platforms/<platform>/`。

## 按场景处理

- 框架变更：定义或保持平台无关的协议，增加针对性的契约测试，并验证所有已注册平台；不要新增平台分支。
- 新平台或新接口：按参考手册中的平台资产链路创建 manifest、客户端、数据、Schema、测试和 README；使用公共 fixture，并在完成前登记覆盖映射。
- 新需求接口包：测试归入已有业务模块，使用稳定的 `requirement` 和 `case_id` marker，追加平台覆盖映射；执行时间不能成为测试身份的一部分。
- 契约或响应字段变更：先比较基线与当前快照，区分破坏性和兼容性变更，再按需同步客户端、数据、Schema、断言、接口清单、覆盖映射和文档。禁止静默刷新快照，也不能通过删除失败用例掩盖漂移。
- 线上用例不稳定或被阻塞：先校验运行时配置，检查真实响应和依赖状态；只为有明确异步状态转换的场景做有界轮询，并区分环境前置不足与产品断言失败。

## 必须遵守

- 写入型测试通过平台数据工厂和 `DataScope` 创建资源；生成唯一名称，创建成功后立即登记清理，并依赖逆序清理。
- 不硬编码共享资源 ID、执行顺序、凭证、URL 或未记录在契约中的请求字段。无法安全构造的状态应通过只读发现或显式环境变量提供。
- 日常测试和 CI 固定使用仓库内已提交的契约快照。远程契约拉取和快照替换只允许维护者显式执行，且必须校验、生成报告并原子更新。
- 不假定所有接口使用同一种响应包裹结构。使用公共断言 helper，并针对已知错误响应形状显式处理。
- Schema 用例和覆盖映射一起新增或修改；保持 case ID 稳定，参数边界优先使用 `pytest.mark.parametrize` 和平台 YAML 数据集。

## 验证

先运行受影响的窄范围测试，再根据改动执行仓库门禁：

```bash
.venv/bin/pytest -m contract -q
.venv/bin/pytest -m 'not live' -q
.venv/bin/pytest --collect-only -q
git diff --check
```

线上改动要在运行时校验后执行对应平台的 `platforms/<platform>/test.sh`。报告中要把跳过的用例、缺失的外部前置和未执行的线上检查，与代码失败分开说明。需要场景检查清单、命令路由和常见故障处理时，阅读 [references/maintenance-playbook.md](references/maintenance-playbook.md)。
